# Music Library – agent notes

Native macOS music library app (SwiftUI) built with SwiftPM only; no Xcode project, no third-party dependencies. Works with Xcode or just the Command Line Tools. MIT licensed.

- `Sources/MusicLibraryCore`: all non-UI logic (SQLite, tags via ffprobe/ffmpeg, organizer, MusicBrainz/AcoustID/CoverArt clients, import, export, search, stats).
  - Search: `Search.swift` parses the query language (`SearchQuery`, filter keys in `SearchFilterKey.all`); `SearchIndex.swift` is an immutable in-memory index (matching, ranking, completions, spelling correction). The app rebuilds it off the main thread on every library reload; smart playlists are saved query strings evaluated against it.
  - `Themes.swift`: theme palettes (8 base colors each; card, separator and chart ramps are derived). `ThemeTests` enforce contrast for every palette, so new themes must pass them. The app applies a theme with `.themedRoot(_:)`; use `.subtext` instead of `.secondary` for secondary text (`Text` ignores custom hierarchical styles). Sidebar counts use `.sidebarBadge(_:)`, not `.badge`: themes draw their own pill (`badgeFill`/`badgeText`) because the native badge's number is too faint on some palettes.
  - `LastFM.swift`: signed Last.fm client (injectable transport for tests), `ListenTracker` (scrobble rules), `ScrobbleQueue` (persisted to Application Support). `Scrobbler` in the app connects them to the player.
  - `ArtistInfo.swift`: artist info from MusicBrainz (url-rels, genres), Wikidata, Wikipedia summaries and Last.fm; pure parsers and `ArtistInfo.assemble` are tested with real fixtures, `InfoFetcher` does the network calls (artists and albums). `ArtistResolver` picks the MusicBrainz artist (multi-artist credits need a confident name match). The app's `ArtistInfoStore` caches it in the `artist_info` table and `<root>/Artist Images`. External URLs (MusicBrainz relations, Wikipedia/Last.fm pages, and anything read back from the `artist_info`/`album_info` caches) are untrusted: parse them with `URL(webLink:)` and only pass `url.webLink`/`isWebLink` URLs (http/https with a host) to `Link`/`openURL`.
  - `AlbumInfo.swift`: album info from the MusicBrainz release group (rating, filtered genres, review links), the matched release's track list, Wikipedia and Last.fm; `AlbumTracklist.merge` lines the release up with the library's tracks. Cached in `album_info` by `AlbumInfoStore` (opening an album fetches it first).
  - `MusicDNA.swift`: `CollaborationGraph`, people from credits/tags/track artists (merged by MusicBrainz ID, then normalized name; non-musical release credits like photography are skipped) linked by shared tracks, plus the capped breadth-first neighborhood and radial layout shown on the Music DNA page. Rebuilt with the search index. In the UI, show people's names with `PersonLink`/`PersonLinks`/`PeopleRow` (pass `model.showMusicDNA` as `open`) so they open Music DNA.
  - `PlayQueue.swift`: the Spotify-style play queue (the list playback started from, plus songs queued with Play Next, which always play next; Add to Queue appends to the end). `Player` wraps it; `QueueView` shows it in the window's inspector. The queue and position are saved on quit (and at each track change) as a `PlayQueue.Snapshot` of track IDs in Application Support (`player-state.json`, `AppModel.savePlayerState`) and restored paused at launch; a restored song isn't loaded (no output-format change, no play recorded) until it's played.
  - Liked songs: the `liked_tracks` table (track id, liked date; cascades when a track is removed), `AppModel.likedDates`/`setLiked`. Liked Songs is a built-in playlist (`SidebarItem.likedSongs`, `ExportItem.likedSongs`, most recently liked first) that can't be renamed or deleted. Show the heart with `LikeButton(model:track:)` (safe in `Table` cells) and `LikeMenuButton` in song context menus.
  - Listening history: the `plays` table (one row per listen, `counted` = met the scrobble rule), recorded by `AppModel` from player events.
  - `LibraryExport.swift`: `LibraryExporter` copies tracks to another folder using the library's layout (data only, via a hidden partial file and a rename; it never overwrites or deletes), writes `Playlists/*.m3u`, and can replace `<dest>/library.sqlite` with a `VACUUM INTO` snapshot (bringing `Artist Images` up to date with it). `ExportPreview` scans a destination's `Music` folder and merges it with the plan, per album folder, for the Export List's split view. The app's Export List (`ExportItem`, `ExportViews.swift`) collects albums, songs, artists and playlists and resolves them to tracks at export time; the destination is a setting (`AppModel.exportDestination`). `PlaylistExporter` (in `Import.swift`) is the older one-folder-per-playlist export.
  - `Stats.swift`: `LibraryStats`, everything shown in the Library pane of Insights, computed in one pass with data-driven list sizes and bucket granularity.
  - `ListeningStats.swift`: `ListeningStats`, the Listening pane of Insights, from the `plays` rows (`Database.plays()`) for one period (7 days, 30 days, 12 months, all time): top songs/artists/albums/genres, activity over time, a weekday × hour clock, eras vs the library, skips, streaks and forgotten favorites. `AppModel.loadListeningIfNeeded` computes it in the background and refreshes it when `historyVersion` (bumped per recorded listen) changes.
  - `AlbumOwnership.swift`: albums you own (`AlbumPurchase`: optional purchase day and price), saved per album key (`SearchIndex.albumKey`) in the `album_ownership` table, apart from the tracks, so re-importing keeps them. `PurchaseDay` is a calendar day with no time zone; prices are `Decimal`, stored as POSIX decimal text in the locale's currency (`currencyCode` in the app). Rows are untrusted and read back with bad dates/prices as unknown. `OwnershipStats` is the Owned pane of Insights (library albums only). The app edits ownership on the album page (`AlbumOwnershipSection`) and when ripping a CD (`CDOwnershipPanel`; saved for the matched release when ripping starts, then on every change); `AppModel.purchases`/`purchasesVersion`, `loadOwnershipIfNeeded`.
  - `AlbumCover.swift`: `AlbumCoverWriter` gives an album a new cover: `cover.jpg` in its folders (atomic write) and, optionally, the art embedded in its mp3/flac/m4a library files (`TagWriter.replaceEmbeddedCover`: remux with `-c copy` to a hidden temp file, then `replaceItemAt`; audio and tags kept). Paths go through `Track.coverURL`/`resolvedFileURL`. The app's `AlbumCoverSheet` (album page: toolbar, hover on the cover, or dropping an image on it) finds covers on the Cover Art Archive for the tagged release/release group and `MusicBrainzClient.searchReleases(album:artist:)` results, or takes a file, a dragged web image or the clipboard; `CoverImage.jpeg` converts to JPEG at most 1600 px. `AppModel.coverRevision` is bumped after a change; pass it to `CoverThumb(revision:)` so views reload the same cover.jpg.
  - `LibraryCatalog.swift`, `LibraryCatalogParser.swift`, `LibraryCatalogMatching.swift`: a public library catalog run on Aspen Discovery (default https://natick.minlib.net, Minuteman Library Network). Aspen's JSON API is IP-restricted, so the catalog is read like its website: `/Search/Results` (20 per page; filters `format`, `owning_location` (any of), `available_at`; negated filters are ignored), `getCopyDetails` (copies per library), `getRelatedManifestations` (editions with UPCs), the work page (contributors, contents), the Location facet popup (library list), `loginUser`, `getCheckouts`, and lists (`getSaveToListForm` for the patron's lists, `saveToList`, `/MyAccount/MyList/<id>` pages, `?delete=<entry>`). `CatalogParser` cuts result pages into one fragment per result before parsing (tidy HTML mis-nests them); fixtures `minlib_*` are real pages. `CatalogEnricher` matches a title on MusicBrainz by barcode (falling back to a release group search) and fetches its `AlbumInfo`; results are cached in `catalog_info`. `CatalogOwnership` says which library album a catalog title is (release group, then normalized title + compatible artist).
  - `ApplePreviews.swift`: 30-second song previews of library CDs you don't own, from Apple's iTunes Search API (no account or key). `ApplePreviewFinder` tries an Apple Music link on the MusicBrainz album, then barcodes (Apple's often differ from the CD's), then a search on artist and title (`ApplePreviewMatcher.bestAlbum`); `ApplePreviewMatcher.lineUp` matches Apple's songs to the track list. `ApplePreviewClient` spaces requests 3 s apart (Apple allows about 20 a minute), so previews are fetched only when a title's page is opened, never during scans. Results are cached in `catalog_previews`; preview and page URLs must be https on apple.com (`ApplePreviewParser.isAppleURL`, checked again when read back from the cache). Fixtures `itunes_*` are real responses. The app's `PreviewPlayer` (`AppModel.previews`) plays them apart from `Player`: previews never join the queue, history or Last.fm, and starting either one pauses the other.
- `Sources/MusicLibrary`: SwiftUI app (`AppModel`, `Player`, `ImportController`, views).
- `Tests/MusicLibraryCoreTests`: Swift Testing suites; fixtures in `Fixtures/`.

## Environment (Command Line Tools only; not needed with Xcode)
SwiftUI's `@State`/`@Environment` macro plugin is not shipped with the CLT, so the default macOS 27 SDK cannot compile the app target. Use the macOS 26 SDK:

    export SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk

`scripts/build-app.sh` does this automatically. Without Xcode, `Package.swift` adds the CLT swift-testing macro plugin path to the test target. ffmpeg/ffprobe are found in /opt/homebrew/bin, /usr/local/bin or `PATH` (fpcalc optional).

## Commands
- Build: `swift build`
- Test: `swift test` (needs ffmpeg; generates audio with `ffmpeg -f lavfi`)
- Live network tests (MusicBrainz, Cover Art Archive): `MUSICLIB_LIVE_TESTS=1 swift test --filter LiveTests`
- Build app bundle: `scripts/build-app.sh` -> `build/MusicLibrary.app` (ad-hoc signed; `VERSION=…`, `BUILD=…`, `UNIVERSAL=1` for arm64 + x86_64, which needs Xcode; `SIGN_IDENTITY=…` signs with a certificate; one with a Team ID keeps keychain access across rebuilds)
- Regenerate the app icon (`Resources/AppIcon.icns`, `AppIcon-1024.png`): `swift scripts/make-icon.swift` (needs the `SDKROOT` above).
- Run: `open build/MusicLibrary.app` or `swift run MusicLibrary`

## CI and releases
- `.github/workflows/ci.yml` builds, runs the tests and builds a universal app on every push and pull request (macOS runner, newest stable Xcode, ffmpeg from Homebrew).
- Pushing a tag `vX.Y.Z` also publishes a GitHub release with `MusicLibrary-X.Y.Z-macOS.zip` (ad-hoc signed, not notarized) and its SHA-256.
- README screenshots live in `docs/screenshots/` (1600 px wide, taken from a real library window).

## Library catalog
- The catalog site sits behind Cloudflare, which blocks URLSession (and curl) for pages and AJAX: `LibraryCatalogClient` loads them with `fetch()` inside a hidden `WKWebView` (persistent data store, so sign-ins survive), one request at a time with a short gap. Cover images (`bookcover.php`) redirect to other hosts, so they load with URLSession instead. Requests are `.interactive` (0.8 s apart) or `.background` (3 s apart: scans and lookups). A 429 sets a cool-down (Retry-After, or 60 s doubling up to 15 min) during which background work waits and interactive requests fail with `CatalogError.rateLimited`; background lookups also hold while a scan runs, so only one stream hits the site. Don't hammer the site while developing.
- `LibraryCatalogStore` (in `AppModel.catalog`) holds the query (persisted), client-side filters (ownership, "not on the shelf", which the catalog can't do), the account (password in the keychain), copies and the MusicBrainz lookup queue. Results' status ("On Shelf"…) is relative to the catalog site's own library. The list chosen in Settings (`listId`) is where Add to List goes; `listEntries` drive the bookmark badges and the list page.
- Downloaded catalog (`LibraryCatalogIndex.swift`, `LibraryCatalogDownload.swift`): every CD the libraries in `downloadLibraries` own is scanned page by page ("recently added" order) into `catalog_items` (`CatalogRecord.upsert` per page, so an interrupted scan resumes from `ScanState` in the cache; `CatalogRecord.prune` drops titles only after a complete scan), refreshed when older than 12 hours (at launch once something was downloaded, and when Library CDs opens), and looked up on MusicBrainz through `downloadQueue`, behind the user's own `lookupQueue`. `CatalogIndex` searches it in the app's query language (`SearchQuery`, with catalog meanings for `title:` = songs, `time:` = album length, `track:`/`disc:` = counts, `added:` = first seen) plus `CatalogSearchQuery` filters (`is:owned|available|out|onlist`, `library:`, `rating:`). Library CDs shows it when downloads exist; the live website search is its "Search the Whole Network Live" mode.
- Caching: MusicBrainz details in `catalog_info` (60 days; 14 for no match); covers and work pages on disk in `~/Library/Caches/MusicLibrary/Catalog` (`LibraryCatalogCache`); results pages for 30 minutes (Reload skips them); copies for 10 minutes in memory.

## Keychain
- `KeychainStore.app` keeps every secret in ONE generic-password item (`secrets`, a JSON dictionary) read once per launch: macOS asks to allow keychain access once per item for each new ad-hoc-signed build. Don't add separate items; older per-secret items are moved in when first read.

## Conventions
- UI layout: the player bar sits below the `NavigationSplitView`, not inside the detail column (views pushed on a `NavigationStack` draw over siblings in their column on macOS). Pages push `AlbumSummary`/`ArtistSummary` onto the single root stack via `NavigationLink(value:)`; don't nest another `NavigationStack`.
- Views inside `Table` cells must not read `@Environment(AppModel.self)`: cells don't always receive it and the app crashes while scrolling. Pass the model, an object from it, or an action from the parent instead.
- Library layout: `<root>/Music/<AlbumArtist|Artist>/<Album> (<Year>)/<NN> - <Title>.<ext>`, DB at `<root>/library.sqlite`, track paths stored relative to root.
- Track paths come from a `library.sqlite` that may have been made elsewhere: read, copy, trash or export a track's file only through `Track.resolvedFileURL(root:)`/`coverURL(root:)` or `LibraryPath.resolve` (they reject `..`, absolute paths and symlinks leading outside the folder). `fileURL(root:)` is for display.
- `.TOC.plist` is read from every mounted volume (not only real CDs), so it is untrusted: `CDTOC.parse` rejects blocks outside the Red Book range (`CDTOC.maxBlock`) and non-increasing tracks; keep block arithmetic overflow-safe.
- Source files are never modified; tags are written only to the library copy (mp3, flac, m4a).
- MusicBrainz IDs from tags and `library.sqlite` are untrusted: `TagReader.parse` and DB row loading drop non-UUIDs via `TrackMetadata.validateMBIDs()`, and ID lookups build URLs with `MusicBrainzClient.lookupURL` (throws on invalid IDs). Never force-unwrap a URL built from an ID.
- Secrets (API keys, shared secrets, session keys) go in the keychain via `KeychainStore` (`Keychain.swift`), never in `UserDefaults`; values older versions left in defaults are moved over once with `migratedString(for:from:key:)`.
- MusicBrainz requests are rate limited (>=1.1 s) and identify the app with `AppInfo.userAgent`; tests must not hit the network unless `MUSICLIB_LIVE_TESTS=1`.
- Exported playlists: build `.m3u` text only with `PlaylistExporter.m3uContents`, which keeps tag/path line breaks (control characters, U+2028/U+2029) from starting new entries.
